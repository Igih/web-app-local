# 代码Agent任务书：图像入库前质量体检系统 V1.0

请先完整阅读随附《图像入库前质量体检_详细设计方案_v1.md》，并以其作为本项目Q1～Q6的范围、数据契约和验收依据。

## 项目背景

现有网站已开发完成，使用 Docker Compose + Nginx + Node/前端 + FastAPI + Python + PostgreSQL，支持按文件/目录路径导入图像、六类花卉、两级图片类型（实拍/手绘 × 可见光/红外）、每图最多五个自定义标签、方案B SHA-256存储。现在需要在正式入库前添加质量体检功能，**仅产出动态筛选建议和逐图CSV，不直接删除/修改源图，不重构旧业务**。

## 开发规约

1. 增量开发：复用现有身份认证、图片导入、扫描批次、Worker、数据库连接、ORM、迁移机制、前端组件、Docker卷挂载。不随意改旧菜单、旧API或存储策略。
2. 先完成项目审查，确认真实文件路径和数据表，**第一轮禁止修改代码、数据库和Compose**。
3. 质量指标与阈值独立存储；调整阈值只重新评估候选数据，不重新读取图片或重新计算指标。
4. 每个数值型指标必须展示：分布直方图、刻度与单位、阈值竖线、图表下方的双阈值滑块、启用开关、当前命中数量和进入对应图片列表入口。亮度需支持双侧阈值；离散文件有效性与SHA重复使用分类图不硬套滑块。
5. 同时显示“建议入库/建议复核/建议排除”三类实时互斥数量；交集原因不能简单相加。
6. 支持实拍可见光、实拍红外、手绘可见光、手绘红外及未指定画像的独立质量规则，保留16-bit红外原图及正确灰度范围；不得直接把可见光阈值套到红外。
7. 仅实现Q1基础指标、Q2 SHA与pHash、Q3阈值、Q4 UI、Q5建议、Q6 CSV，FiftyOne/Agent/深度视觉特征留作二期。
8. 一条扫描源文件对应CSV一行；包含正常、损坏、完全重复、疑似相似图片。CSV必须记录原始指标、异常原因、建议、规则及算法版本；规则确认时冻结快照，滑块预览不自动创建大量永久版本。
9. 对路径、权限、异常重试、幂等、数据库约束、旧系统回归及容器重建进行测试。
10. 禁止以“写完代码”宣告完成，必须提供可复现的测试结果；无法验证就明确说明。

## 第0轮（现在执行）：只审查，不修改

请查看：
- Docker Compose、挂载目录与现有后台服务。
- FastAPI路由、Worker、认证和现有导入生命周期（扫描、确认、入库）。
- PostgreSQL表、模型与迁移机制，尤其候选文件/批次/图片来源表。
- 前端路由、菜单、UI组件、图表库和CSV导出习惯。

输出以下报告：
1. 真实项目结构与需要复用的组件；
2. 新质量流程在现有导入流程中的准确插入点；
3. Q1–Q6模块与文件新增/修改清单；
4. 数据库增量迁移方案、索引与兼容性；
5. 质量指标的实现版本、预处理及四类画像的默认规则（未校准指标仅作为候选）；
6. API契约、直方图与滑块的数据交互、综合建议与CSV结构；
7. 安全与性能风险，测试计划，具体回滚方案；
8. 不能从当前代码确定的内容，请标为“待核实”，不要猜测。

**本轮不得写任何代码和SQL，不得执行数据库迁移或修改Docker配置。**

## 下一轮按顺序逐模块执行

- **Q1**：只实现指标计算、原始结果存储、缺失状态及版本；提供测试数据和数值校验。
- **Q2**：只实现SHA/pHash与来源区别、同批次/正式库近重复；提供候选对和搜索覆盖测试。
- **Q3 + Q5**：实现阈值配置、类型画像、规则约束、综合建议纯函数和边界测试。
- **Q4**：逐指标分布卡片、图下双阈值、实时总数、缩略图列表、并发过期响应处理。
- **Q6**：冻结评估快照、后台CSV导出、规则JSON、行数/哈希与追溯校验。
- **全链路**：功能回归、1000张→10万张→100万张性能测试，人工校准四类图像。

每次只执行用户指定的一轮：先列修改文件和回滚方式，再修改、测试并报告结果，等待用户验收后再进入下一模块。

## 必须报告的验收结果

- 每张质量分布图和滑块是否可用、各指标方向和阈值边界是否正确。
- 滑块变化时是否未重新分析图像，三类数量加总是否准确。
- 源文件是否保持字节不变，16-bit数据是否不被截断，文件损坏是否被报告。
- pHash搜索覆盖范围与同批次/已有库查重是否真实有效。
- CSV与冻结评估快照是否一一对应，逐文件行数与错误列是否符合规范。
- 原有功能是否通过回归测试，性能是否有实测证据。
